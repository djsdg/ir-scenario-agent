## 描述 / description

系统正常运行时，类型 A 部件可能出现异常，导致单节点 IO 进程反复 core 或复位，也可能出现校验错误和数据不一致。现有检测机制不能覆盖全部异常，需要根据故障表现识别异常，并在确认后对节点执行复位修复、恢复或下电隔离，同时产生告警。

## 5W2H

### Who

本系统

### When

系统正常运行时，目标部件出现异常；单节点 IO 进程在观察窗口内反复 core 或复位。

### Where

系统中的类型 A 部件及其所在节点，重点关注 IO 进程。

### What

改进单节点 IO 进程反复 core 或复位的异常检测、节点修复和隔离机制。

### How

1. 采集单节点 IO 进程的 core、复位、校验错误和数据不一致等故障表现。
2. 根据可配置阈值判断是否达到异常检测条件。
3. 对明确的异常执行复位修复或下电隔离，并记录处理结果。
4. 对反复 core 或复位的节点先排除软件异常干扰，再执行恢复、修复或隔离。
5. 检测到异常后产生告警，并保留诊断信息。
6. 仅对 IO 进程进行监控。

### Why

当前检测机制无法有效检测所有部件异常，可能导致关键进程反复复位、节点持续异常或数据不一致，影响系统故障发现和服务恢复。

### How Much

- 非明确异常每月最多处理一个节点。
- 提升异常检测能力。
- 检测到异常后必须产生告警。
- 检测阈值支持调整。
- 对系统性能无明显影响。

## 约束 / constraints

1. 只监控 IO 进程，不扩大到其他进程。
2. 只针对类型 A 部件。
3. 检测属于事后检测，不能保证数据不损坏。
4. 数据修复不属于本 IR 范围。
5. 根据进程复位表现判断异常可能存在误判，器件故障率可能上升。
6. 软件异常未排除前，不应直接执行节点隔离。
